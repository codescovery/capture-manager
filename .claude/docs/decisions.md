- 2026-11-18 — Stream measured with a rig (`.claude/scripts/streamrig`, stream-testing.md) and four things changed because of it. (1) Windows Graphics Capture paced a 164 Hz window at 55 fps; `GraphicsCaptureSession.MinUpdateInterval` = 1 ms (build 26100+) is set through the ABI interface `IGraphicsCaptureSession5` (`Helpers/CaptureSessionPacing`, vtable slot 7) instead of raising the target SDK from 19041: smaller change, no-op on older Windows. Capture now 160-165 fps, latency p50 19 -> 12 ms at 720p. (2) Frame pool is `CreateFreeThreaded`, so a busy UI thread does not stall frames; evidence is weak (one 652 ms gap in 32 s before, none in 48 s after). (4) Expected encoder shutdown no longer logged as an error. Kept: the 120 fps cap (82 fps at 164 Hz, even cadence, preferred over an uneven 120). Temporary timing trace used to find the pacing was removed.
